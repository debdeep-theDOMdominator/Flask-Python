1. Flask Introduction

1.1 What is Web Development?

Web development is the process of creating websites and web applications that users access through a web browser. It involves designing user interfaces, processing requests, managing data and returning responses.

Frontend

The part of an application that users see and interact with.

Common technologies: HTML, CSS, JavaScript and React.

Backend

The server-side part that processes requests, applies business logic, authenticates users and communicates with databases.

Common technologies: Flask, Django, FastAPI, Express.js.

Database

Stores and retrieves application data, such as user accounts, products, orders and records.

Examples: PostgreSQL, MySQL, SQLite and MongoDB.

Web server

Accepts HTTP requests and helps deliver responses. In production, it commonly works with a WSGI or ASGI application server.

1.2 Where Does Flask Fit In?

Flask is a Python framework used mainly to develop the backend of web applications. It receives HTTP requests, runs Python code and returns responses such as HTML pages, JSON data or error messages.

Remember: Flask is a backend framework. It can render HTML pages, but it is not a replacement for HTML, CSS or JavaScript. It can also provide APIs to frontend applications such as React.

2. What Is Flask?

2.1 Definition

Flask is a lightweight, open-source web framework written in Python. It provides the essential tools needed to create web applications, including URL routing, request handling, response generation and integration with other Python libraries.

Flask is commonly described as a microframework. The word "micro" does not mean that Flask can only build small applications. It means that Flask keeps its core relatively small and does not force developers to use a large set of built-in components for every project.

2.2 Important Terms

TermMeaning
Framework A collection of tools, conventions and reusable components that helps developers build applications.
Lightweight Provides a relatively small core without requiring many built-in components.
Open-source The source code is available under an open-source licence, allowing permitted use, inspection and contribution.
Microframework A framework with a minimal core that can be extended using additional libraries.
Backend The server-side application logic that processes requests and manages data.
Route A URL rule that determines which application function handles a request.
View function A Python function that handles a request and returns a response.

2.3 How Does Flask Work?

  1. A user opens a URL in a browser or sends a request from a frontend application.
  2. The request reaches the Flask application through a web server.
  3. Flask matches the URL and HTTP method to a registered route.
  4. The corresponding Python view function executes.
  5. The function may validate input, perform calculations or access a database.
  6. Flask sends the response back to the client.
  7. The browser displays the returned page or the frontend processes the returned data.
Example: When a user opens /about, Flask can execute an about() function and return an HTML response containing information about the website.

2.4 What Does Flask Include?

  • URL routing and view functions.
  • HTTP request and response handling.
  • Jinja template integration.
  • Static-file support.
  • Cookie and session support.
  • Error handling and application configuration.
  • Integration with extensions for databases, forms, authentication and other features.

Flask uses the Werkzeug WSGI utility library and integrates the Jinja template engine. These libraries help Flask handle web requests and generate dynamic HTML.

4. What Does Flask Do?

4.1 Handles HTTP Requests

Flask receives requests for URLs and routes them to the appropriate Python function. For example, a request to /products can trigger a function that retrieves product information.

4.2 Generates Responses

A Flask application can return different types of responses:

  • HTML for web pages.
  • JSON for APIs.
  • Plain text for simple responses.
  • Redirects to other URLs.
  • Files or downloads.
  • Appropriate HTTP errors and status codes.

4.3 Processes Business Logic

Business logic consists of rules that determine how an application operates. For example, an online store may calculate a total price, validate an order, check stock or determine whether a user is permitted to access an administrative page.

4.4 Connects to Databases

Flask does not require a particular database. Developers can use Python database drivers or libraries such as SQLAlchemy to work with relational databases. MongoDB can be integrated using an appropriate MongoDB driver or library.

4.5 Supports API Development

An API allows different software applications to communicate. Flask can return JSON data to a React frontend, a mobile application or another service.

Example: A simple JSON API
from flask import Flask, jsonify

app = Flask(__name__)

@app.route("/api/message")
def message():
    return jsonify({
        "message": "Hello from Flask",
        "status": "success"
    })

if __name__ == "__main__":
    app.run(debug=True)

When a client requests /api/message, Flask returns JSON rather than a complete HTML page.

6. Why Flask?

6.1 Reasons to Learn Flask

  1. Python-based: It is suitable for learners who already know Python.
  2. Easy entry point: A small application can be created with only a few lines of code.
  3. Flexible architecture: Developers can choose libraries and organize their applications according to their needs.
  4. API-friendly: It is useful for building backend services for React and mobile applications.
  5. Python ecosystem: It can integrate with data analysis, machine learning and automation libraries.
  6. Incremental learning: Developers can add database access, authentication and other capabilities as the application grows.
  7. Testing support: Flask provides a test client that helps test requests and responses without running a live server.

6.2 When Is Flask a Good Choice?

  • When you want to understand web backend fundamentals.
  • When building a small or medium-sized API or web application.
  • When you want control over libraries and project structure.
  • When integrating Python logic into a web application.
  • When creating a backend for a separate frontend such as React.

6.3 When Might Another Framework Be Better?

Django may be more convenient when you need a built-in admin interface, ORM, authentication system and a highly integrated framework. FastAPI may be more suitable when the primary goal is to build typed APIs with automatic OpenAPI documentation and asynchronous request handling.

These are general guidelines, not strict rules. All three frameworks can support different kinds of applications.

7. Features and Advantages of Flask

7.1 Major Features

1. Minimal Core

Flask provides essential web-development functionality while allowing developers to choose many additional tools independently.

2. URL Routing

Routes map URLs and HTTP methods to Python functions. This makes it possible to define separate behaviour for pages such as /, /about and /products.

3. Jinja Templates

Flask integrates Jinja, a template engine that supports variables, conditions, loops and template inheritance for generating dynamic HTML.

4. Request and Response Objects

Flask exposes information about the incoming request and provides tools for generating the outgoing response.

5. Sessions and Cookies

Flask supports cookies and signed-cookie-based sessions. Sensitive data should not be placed in a default Flask session merely because the session is signed; signing protects integrity, not confidentiality.

6. Extensions

Extensions add capabilities such as database integration, login management, form validation, migrations and caching.

7. Debugging and Testing

Development tools help diagnose errors, while Flask's test client allows developers to test application routes.

7.2 Advantages

AdvantageExplanation
Simple to start A basic application requires very little setup.
Flexible Developers can select their preferred database, authentication and other libraries.
Python integration Useful for applications that rely on Python packages or data-processing workflows.
Lightweight core Does not require every project to use a large collection of built-in components.
Good for APIs Routes can return JSON and support clients written in different technologies.
Extensible Additional capabilities can be introduced as project requirements evolve.

8. Limitations and Disadvantages of Flask

8.1 Major Limitations

  • Fewer built-in features: Database integration, authentication and other capabilities generally require extensions or additional libraries.
  • Architectural responsibility: Developers must choose a sensible project structure as the application grows.
  • Library selection: Choosing and maintaining compatible extensions requires care.
  • Security responsibility: Authentication, authorization, validation, CSRF protection and other security controls must be implemented correctly.
  • Production setup: The built-in development server is not designed to be the production deployment server.
  • Async considerations: Flask supports asynchronous views, but it is based on WSGI. Async support does not automatically make it equivalent to an ASGI-native framework for long-lived concurrent connections.

8.2 Are These Limitations Serious?

Not necessarily. Flask's flexibility is useful when a project needs only selected capabilities. However, a team must plan the architecture, dependencies, security and deployment instead of assuming that every feature is automatically included.

Security warning: Never deploy a public production application with Flask's development debugger enabled. The interactive debugger can expose extremely sensitive capabilities.

9. Flask vs Django vs FastAPI

9.1 Introduction to Each Framework

Flask: A lightweight WSGI web framework with a minimal core and an extension-based ecosystem.

Django: A high-level Python web framework that includes many integrated features such as an ORM, authentication, an admin interface and a form system.

FastAPI: A Python framework focused on APIs, type annotations, request validation and automatic OpenAPI documentation. It is ASGI-based.

9.2 Comparison Table

Feature Flask Django FastAPI
Main focus Flexible web applications and APIs Full-featured web applications APIs and typed request handling
Core approach Minimal core Integrated, batteries-included API-focused framework
Learning curve Generally gentle at the beginning More concepts and conventions initially Accessible with Python and type-hint knowledge

Built-in admin interface No Yes No

Typical use Custom web backends and APIs Database-driven portals and full web applications APIs, validation-heavy services and async workloads

9.3 What Is WSGI?

WSGI stands for Web Server Gateway Interface. It is a standard interface between Python web applications and compatible web servers or application servers.

Flask is a WSGI application. In production, a WSGI server such as Gunicorn can run the application. On Windows, other deployment arrangements may be more appropriate depending on the hosting platform.

9.4 What Is ASGI?

ASGI stands for Asynchronous Server Gateway Interface. It supports asynchronous request handling and protocols such as WebSockets. FastAPI is designed for the ASGI ecosystem.

9.5 Which One Should You Choose?

RequirementPossible choice
Learn Python web development fundamentals Flask
Build a full database-driven portal with a built-in admin panel Django
Build an API with typed validation and automatic API documentation FastAPI
Build a custom Python backend for React Flask or FastAPI; requirements determine the better fit.
Build an application using Python data science libraries Flask or FastAPI, depending on the interface and workload.
There is no universal winner. Consider the project's features, team experience, integration requirements, security needs and deployment environment before choosing a framework.

11. Installing Python and Flask

11.1 Prerequisites

Before installing Flask, ensure that you have:

  • Python 3 installed.
  • A terminal such as Command Prompt or PowerShell.
  • A code editor such as Visual Studio Code.
  • Basic knowledge of Python functions, variables, imports and conditionals.

11.2 Check Python Installation

On Windows, open Command Prompt or PowerShell and run:

Windows terminal
py --version

You can also try:

python --version

A successful command prints the installed Python version. If neither command works, install Python from the official Python website and ensure that the installation is available from your terminal.

Official website: Python Downloads

11.3 Create a Project Folder

mkdir flask_learning
cd flask_learning

The first command creates a folder named flask_learning. The second command moves the terminal into that folder.

11.4 Create a Virtual Environment

py -m venv .venv

This creates an isolated Python environment inside the .venv directory. The next section explains why this is important.

11.5 Activate the Environment on Windows

For Command Prompt:

.venv\Scripts\activate.bat

For PowerShell:

.\.venv\Scripts\Activate.ps1

If PowerShell blocks activation, you can use Command Prompt instead. Avoid changing system-wide execution policies unnecessarily.

11.6 Install Flask

With the virtual environment activated, run:

python -m pip install --upgrade pip
python -m pip install Flask

Python package names are generally case-insensitive for installation, but Flask is the conventional package name.

11.7 Verify the Installation

python -m flask --version

This prints the Flask version and related environment information. You can also test the import: 

python -c "import flask; print(flask.__version__)"
The flask.__version__ attribute is deprecated in recent Flask versions and may be removed in a future release. Prefer python -m flask --version or Python's package metadata API for version checks.

12. Virtual Environments in Python

12.1 What Is a Virtual Environment?

A virtual environment is an isolated Python environment for a project. It allows the project to have its own installed packages without relying on the same set of third-party packages used by every other project.

12.2 Why Is It Necessary?

Imagine that you have two Python projects:

  • Project A requires one version of a library.
  • Project B requires a different compatible version.

Installing every package globally can cause dependency conflicts. Separate virtual environments help each project maintain its own dependencies.

12.3 Advantages

  • Reduces dependency conflicts between projects.
  • Keeps project dependencies separate from system packages.
  • Makes development and testing environments easier to reproduce.
  • Helps document project dependencies in a requirements file.
  • Makes project setup easier for teammates and deployment environments.

12.4 Common Virtual Environment Commands

12.5 Understanding requirements.txt

The requirements.txt file records Python package dependencies. Running pip freeze records the installed package versions, which helps recreate the environment.

Example of a requirements file:

requirements.txt
Flask==3.1.2

This is an illustrative version pin, not a requirement to install that exact release. Record the version actually installed and compatible with your project.

13. Creating Your First Flask Application

13.1 Create app.py

Inside the project folder, create a file named app.py. Write the following code:

app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello, Flask! My first web application is running."

if __name__ == "__main__":
    app.run(debug=True)

13.2 Line-by-Line Explanation

Line 1: Import Flask

from flask import Flask

This imports the Flask class from the Flask package. The class is used to create a Flask application object.

Line 2: Create the Application

app = Flask(__name__)

This creates the Flask application instance and stores it in the variable app.

__name__ is a Python variable that identifies the current module. Flask uses it to help determine the application's resource locations, including templates and static files.

Line 3: Register a Route

@app.route("/")

This decorator registers the URL path / with the function immediately below it. The path / is the root URL of the application.

Lines 4–5: Define the View Function

def home():
    return "Hello, Flask! My first web application is running."

When a request matches the route, Flask calls home(). The returned string becomes the body of the HTTP response.

Lines 6–7: Run the Application

if __name__ == "__main__":
    app.run(debug=True)

This condition checks whether the Python file is being run directly rather than imported as a module. If it is being run directly, the development server starts.

The debug=True option enables the development debugger and automatic reloading when supported. It is useful during local development but must not be enabled in production.

13.3 Run the Application

Activate your virtual environment and run:

python app.py

Flask starts a local development server. The terminal will display a local URL, commonly: 

http://127.0.0.1:5000

Open that address in your browser. You should see:

Hello, Flask! My first web application is running.

13.4 Run Using the Flask CLI

You can also start the application with Flask's command-line interface:

flask --app app run --debug

Here, --app app tells Flask to locate the application in app.py. The --debug flag enables development debugging.

Choose either python app.py or the Flask CLI command. You generally should not start two servers on the same port at the same time.

14. Introduction to Routing

14.1 What Is Routing?

Routing is the process of matching an incoming URL and HTTP method to the Python function that should handle the request.

14.2 Multiple Routes

app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Welcome to the home page."

@app.route("/about")
def about():
    return "This is the about page."

@app.route("/contact")
def contact():
    return "Contact us here."

if __name__ == "__main__":
    app.run(debug=True)
URLFunctionResponse
/home()Home page message
/aboutabout()About page message
/contactcontact()Contact page message

14.3 Dynamic Routes

A dynamic route accepts a value as part of the URL. For example, a student profile might be identified by a student ID. 

@app.route("/student/<int:student_id>")
def student(student_id):
    return f"Student ID: {student_id}"

Visiting /student/25 passes the integer 25 to the view function.

The int: converter restricts this URL segment to an integer. Flask also supports other converters, including string, float, path and uuid.

14.4 HTTP Methods

HTTP methods indicate the intended action of a request. Flask routes can be configured to accept one or more methods.

MethodCommon purpose
GETRetrieve or display information.
POSTSubmit data or create a resource.
PUTReplace a resource or update it according to the API's design.
PATCHPartially update a resource.
DELETEDelete a resource.

Example of a route accepting GET and POST:

from flask import request

@app.route("/submit", methods=["GET", "POST"])
def submit():
    if request.method == "POST":
        return "Form submitted successfully."

    return "Display the form here."

Detailed form handling, validation and HTTP status codes will be covered in later modules.

15. Flask Development Server

15.1 What Is the Development Server?

Flask includes a development server that makes it easy to run and test an application locally. It allows a browser or another HTTP client to send requests to your Flask application.

15.2 Understanding the Local URL

Consider this URL:

http://127.0.0.1:5000
PartMeaning
httpThe HTTP protocol.
127.0.0.1The IPv4 loopback address, referring to the local computer.
5000The port number on which Flask commonly listens by default.

15.3 Change the Port

app.run(port=8000, debug=True)

The application will listen on port 8000, provided that the port is available.

Using the CLI:

flask --app app run --port 8000 --debug

15.4 Make the Server Accessible on a Local Network

flask --app app run --host 0.0.0.0 --port 5000

Binding to 0.0.0.0 allows the server to listen on available network interfaces. Other devices may be able to access it through the computer's LAN IP address if network and firewall settings permit.

Do not expose the development debugger to an untrusted network. Binding to 0.0.0.0 can make your application reachable by other devices. Use this only when you understand the network and security implications.

15.5 Debug Mode

Debug mode can provide:

  • Automatic reloading after supported code changes.
  • Detailed error pages during development.
  • More convenient debugging while building the application.

However, debug mode should be disabled in production.

15.6 Development Server vs Production Server

Development serverProduction server
Designed for local development and testing. Designed for serving real users with an appropriate deployment setup.
Often uses Flask's reloader and debugger. Runs with debugging disabled and uses production configuration.
Convenient for quick experiments. Requires appropriate process management, monitoring and security.
Not recommended for production deployment. Commonly uses a WSGI server such as Gunicorn for Flask.

16. Complete Application Workflow

The following example connects the main concepts introduced in this module.

Step 1: The user enters a URL in the browser.

Step 2: The HTTP request reaches the Flask application.

Step 3: Flask finds the matching route.

Step 4: The associated Python function executes.

Step 5: The function creates a response.

Step 6: Flask sends the response to the client.

Step 7: The browser displays the result.

Example: Returning a Dynamic Greeting

from flask import Flask

app = Flask(__name__)

@app.route("/hello/<name>")
def hello(name):
    return f"Hello, {name}! Welcome to Flask."

if __name__ == "__main__":
    app.run(debug=True)

If the user visits /hello/Alex, the route passes Alex to the function. The response becomes:

Hello, Alex! Welcome to Flask.

This example demonstrates URL routing, a view function, a dynamic URL segment and response generation.

17. Common Errors and Their Solutions

Error 1: No Module Named 'flask'

Possible cause: Flask is not installed in the Python environment being used.

Solution:

python -m pip install Flask

Ensure that the virtual environment is activated first.

Error 2: Python Command Not Found

Possible cause: Python is not installed correctly or is not available in the terminal's PATH.

Solution: On Windows, try py --version. If necessary, install Python from the official website.

Error 3: Port Already in Use

Possible cause: Another process is already listening on the port.

Solution: Stop the other development server or select another port.

flask --app app run --port 8000

Error 4: Address Not Found in Browser

Possible cause: The server is not running, the URL is incorrect or the application is listening on another port.

Solution: Check the terminal output and open the URL shown by Flask.

Error 5: PowerShell Blocks Environment Activation

Use the Command Prompt activation command as an alternative: 

.venv\Scripts\activate.bat

Error 6: Changes Are Not Appearing

Confirm that you edited the correct file and that the expected server is running. Restart the development server if necessary. Debug mode normally enables reloading for supported changes.

Error 7: 404 Not Found

A 404 response means the requested URL does not match an available route, or the application intentionally returned that status. Check the URL path and registered routes.
